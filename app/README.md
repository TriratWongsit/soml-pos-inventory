# SOML — ระบบจัดการคำสั่งซื้อและตรวจสอบคลังสินค้า

ซอร์สโค้ดของระบบสำหรับโครงงาน SE02 เอกสารข้อกำหนดและปริญญานิพนธ์อยู่ในโฟลเดอร์ `../Documents/`

เอกสารนี้คือคู่มือติดตั้ง ใช้เป็นหลักฐานทวนสอบ **NFR-09 (การพกพา/ย้ายระบบ)** ด้วย — เกณฑ์คือติดตั้งบนเครื่องใหม่ได้สำเร็จโดยใช้เอกสารนี้เพียงอย่างเดียว ไม่ต้องแก้ซอร์สโค้ด

## ความต้องการของระบบ

| ซอฟต์แวร์ | เวอร์ชัน | หมายเหตุ |
|---|---|---|
| Node.js | 20 LTS ขึ้นไป | มาพร้อม npm |
| MySQL | 8.0 | ต้องใช้กลไกจัดเก็บ InnoDB เท่านั้น (NFR-04) |
| เว็บเบราว์เซอร์ | Chrome / Edge / Firefox รุ่นล่าสุด | ต้องรองรับ WebSocket (NFR-07) |

อุปกรณ์ต่อพ่วงที่ต้องมีสำหรับใช้งานจริง — เครื่องพิมพ์ใบเสร็จความร้อนที่รองรับ ESC/POS ต่อผ่าน USB หรือเครือข่าย และหมายเลขพร้อมเพย์ของร้านสำหรับสร้าง QR รับชำระเงิน

## ขั้นตอนติดตั้ง (macOS)

### 1. ติดตั้ง Node.js

เลือกทางใดทางหนึ่ง

**ทาง ก — ตัวติดตั้งอย่างเป็นทางการ (ง่ายที่สุด)**
ดาวน์โหลดตัวติดตั้ง macOS จาก https://nodejs.org แล้วเปิดไฟล์ `.pkg` ติดตั้งตามขั้นตอน

**ทาง ข — ผ่าน Homebrew**

```sh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install node
```

ตรวจสอบว่าติดตั้งสำเร็จ

```sh
node -v    # ต้องขึ้น v20 ขึ้นไป
npm -v
```

### 2. ติดตั้ง MySQL 8.0

**ทาง ก — ตัวติดตั้งอย่างเป็นทางการ**
ดาวน์โหลด MySQL Community Server 8.0 สำหรับ macOS (ARM ถ้าเป็นชิป Apple Silicon) จาก https://dev.mysql.com/downloads/mysql/ ระหว่างติดตั้งจะให้ตั้งรหัสผ่านของผู้ใช้ `root` — จดไว้ ต้องใช้ในขั้นตอนถัดไป

**ทาง ข — ผ่าน Homebrew**

```sh
brew install mysql
brew services start mysql
```

ตรวจสอบ

```sh
mysql --version
```

### 3. สร้างฐานข้อมูลและใส่ข้อมูลตั้งต้น

```sh
cd app
mysql -u root -p < db/schema.sql     # สร้างฐานข้อมูล soml และตารางทั้ง 7 ตาราง
mysql -u root -p soml < db/seed.sql  # ใส่ข้อมูลสินค้าตัวอย่าง 25 รายการ
```

ตรวจสอบว่าตารางถูกสร้างครบ

```sh
mysql -u root -p soml -e "SHOW TABLES; SELECT COUNT(*) AS products FROM products;"
```

ควรเห็น 7 ตาราง และจำนวนสินค้า 25 รายการ

### 4. ตั้งค่าสภาพแวดล้อม

```sh
cp .env.example .env
```

แล้วแก้ไฟล์ `.env` ให้ตรงกับเครื่องที่ติดตั้ง — อย่างน้อยต้องแก้ `DB_PASSWORD`, `JWT_SECRET` และ `PROMPTPAY_ID`

### 5. ติดตั้ง dependency และสร้างบัญชีผู้ใช้

```sh
npm install
node db/seed-users.js    # สร้างบัญชีทดสอบ 3 บทบาท พร้อมเข้ารหัสรหัสผ่านด้วย bcrypt
```

บัญชีที่ได้คือ `sales01` `wh01` และ `mgr01` รหัสผ่านเริ่มต้นแสดงในผลลัพธ์ของสคริปต์ — ต้องเปลี่ยนทั้งหมดก่อนนำไปใช้งานจริงที่ร้าน

### 6. สร้างใบรับรอง HTTPS

ระบบให้บริการผ่าน HTTPS เท่านั้นตาม **NFR-01** พอร์ต HTTP มีไว้เพื่อส่งต่อไปยัง HTTPS อย่างเดียว

```sh
npm run gen-cert
```

ใบรับรองถูกสร้างไว้ที่ `certs/` (ไม่ถูก commit ขึ้น git) ใช้ได้กับ `localhost` เท่านั้น เบราว์เซอร์จะเตือนว่าไม่น่าเชื่อถือในครั้งแรก ให้กดยอมรับเพื่อใช้งานต่อ เมื่อนำระบบไปติดตั้งใช้งานจริงให้เปลี่ยนไปใช้ใบรับรองที่ออกโดยผู้ให้บริการที่เชื่อถือได้

### 7. รันระบบ

**สำหรับใช้งานจริงที่ร้าน** — สร้างไฟล์หน้าเว็บแล้วให้เซิร์ฟเวอร์เดียวให้บริการทั้งหน้าเว็บและ API

```sh
npm run build     # สร้างไฟล์หน้าเว็บไว้ที่ frontend/dist
npm run serve     # เปิด Backend API และบริการพิมพ์ใบเสร็จพร้อมกัน
```

เปิดเบราว์เซอร์ไปที่ **https://localhost:4000** แล้วเข้าสู่ระบบ ครั้งแรกเบราว์เซอร์จะเตือนเรื่องใบรับรอง ให้กดยอมรับ

การให้บริการหน้าเว็บและ API จากเซิร์ฟเวอร์เดียวกันทำให้ทั้งระบบอยู่ที่ต้นทางเดียว WebSocket เชื่อมต่อตรงโดยไม่ผ่านตัวแทนคำขอ และเข้าถึงผ่าน HTTPS ช่องทางเดียวตาม **NFR-01**

**สำหรับพัฒนา** — ใช้เซิร์ฟเวอร์ของ Vite ที่โหลดหน้าเว็บใหม่อัตโนมัติเมื่อแก้โค้ด

```sh
npm run dev
```

แล้วเปิด https://localhost:5173 เซิร์ฟเวอร์นี้ส่งต่อคำขอ `/api` ไปยัง Backend API ให้เอง ใช้เฉพาะระหว่างพัฒนาเท่านั้น ไม่ใช่ส่วนหนึ่งของระบบที่ส่งมอบ

## การสาธิตระบบ

ขั้นตอนสำหรับวันนำเสนอ ทำตามลำดับนี้บนเครื่องที่ติดตั้งระบบไว้แล้ว

```sh
brew services start mysql@8.0   # ถ้ายังไม่ได้เปิดฐานข้อมูล
cd app
npm run db:reset                # ล้างข้อมูลให้เป็นสภาพตั้งต้น 25 สินค้า 3 บัญชี
npm run build                   # สร้างไฟล์หน้าเว็บ
npm run serve                   # เปิด Backend API และบริการพิมพ์ใบเสร็จ
```

เปิดเบราว์เซอร์ไปที่ **https://localhost:4000** ครั้งแรกจะมีคำเตือนเรื่องใบรับรอง ให้กดยอมรับ

**บัญชีสำหรับสาธิต** รหัสผ่านเดียวกันทุกบัญชีคือ `Soml@2569`

| ชื่อผู้ใช้ | บทบาท | เห็นเมนู |
|---|---|---|
| `sales01` | พนักงานขาย | ขายหน้าร้าน |
| `wh01` | พนักงานคลังสินค้า | คิวรอจ่ายสินค้า · แดชบอร์ดปฏิบัติการ · การแจ้งเตือน |
| `mgr01` | ผู้จัดการ | เมนูทั้งหมด |

### สาธิตจากอุปกรณ์เครื่องอื่น

ใบรับรองที่สร้างโดย `npm run gen-cert` ครอบคลุมหมายเลขไอพีของเครื่องในวงแลนด้วย
ผู้ชมจึงเปิดระบบจากคอมพิวเตอร์หรือมือถือของตนเองในเครือข่าย Wi-Fi เดียวกันได้ที่
`https://<ไอพีของเครื่องที่รันระบบ>:4000` ดูหมายเลขไอพีได้ด้วยคำสั่ง

```sh
ipconfig getifaddr en0
```

การเปิดจากมือถือใช้สาธิตการแสดงผลแบบ Responsive ตาม **NFR-03** ได้ในตัว
เพราะหน้าจอคิวจะเปลี่ยนจากตารางเป็นรายการแบบการ์ดโดยอัตโนมัติ

หากย้ายไปใช้เครือข่ายอื่นแล้วหมายเลขไอพีเปลี่ยน ให้ลบโฟลเดอร์ `certs/` แล้วรัน `npm run gen-cert` ใหม่

### สคริปต์สาธิตอัตโนมัติ

```sh
npm run demo
```

สคริปต์นี้เปิดเบราว์เซอร์สองหน้าต่างพร้อมกันเสมือนพนักงานขายและพนักงานคลังอยู่คนละเครื่อง
แล้วเดินตามสถานการณ์จริงทีละขั้น ตั้งแต่เลือกสินค้า สร้าง QR ยืนยันรับชำระ
จนพนักงานคลังยืนยันจ่ายและระบบตัดสต็อก พร้อมพิมพ์ผลแต่ละขั้นออกทางหน้าจอ
และแสดงให้เห็นว่าการกดยืนยันจ่ายซ้ำถูกปฏิเสธ ภาพประกอบถูกบันทึกไว้ที่ `evidence/demo/`

เหมาะสำหรับกรณีที่ต้องการให้ผู้ชมเห็นภาพรวมทั้งกระบวนการอย่างรวดเร็วโดยไม่ต้องกดเอง

## การทดสอบ

```sh
npm test              # ทดสอบระดับหน่วยและการทำงานร่วมกัน พร้อมรายงานความครอบคลุมโค้ด
npm run test:system   # ทดสอบระดับระบบ TC-05, TC-13, TC-14 และ NFR-01 (ต้องเปิดเซิร์ฟเวอร์ไว้ก่อน)
npm run test:tc06     # ทดสอบการยืนยันจ่ายสินค้าพร้อมกัน TC-06
npm run test:browsers # ทดสอบความเข้ากันได้ของเบราว์เซอร์ NFR-07
npm run capture-evidence  # เก็บภาพหน้าจอทุกหน้าสำหรับบทที่ 4
npm run check:privacy     # ตรวจว่าภาพหลักฐานไม่มีหมายเลขพร้อมเพย์จริงฝังอยู่
```

ชุดทดสอบใช้ฐานข้อมูล `soml_test` แยกจากฐานข้อมูลใช้งานจริง และรีเซ็ตให้เองก่อนเริ่มทุกครั้ง ผลทดสอบทั้งหมดถูกบันทึกไว้ที่ `evidence/`

### หมายเลขพร้อมเพย์ในภาพหลักฐาน

รหัส QR ในภาพหน้าจอเก็บหมายเลขบัญชีของร้านไว้ในตัว ใครที่เปิดที่เก็บโค้ดได้จึงสแกนอ่านหมายเลขนั้นออกมาได้

`npm run capture-evidence` จึงเปิดเซิร์ฟเวอร์ของตัวเองที่พอร์ต 4443 โดย**บังคับใช้หมายเลขสำหรับทดสอบเสมอ** ไม่ว่าค่าใน `.env` จะเป็นอะไร ภาพที่ได้จึงไม่มีหมายเลขจริงฝังอยู่ และไม่ต้องจำสลับค่าเองก่อนเก็บภาพ

ใช้ `npm run check:privacy` ตรวจซ้ำได้ทุกเมื่อ สคริปต์จะถอดรหัส QR จากทุกภาพในโฟลเดอร์หลักฐานและในรูปเล่ม แล้วแจ้งเตือนถ้าพบหมายเลขที่ไม่ใช่หมายเลขสำหรับทดสอบ ควรรันก่อน commit ทุกครั้งที่เพิ่งเก็บภาพใหม่

## โครงสร้างโฟลเดอร์

```
app/
├── db/                 สคริปต์ฐานข้อมูล — schema, ข้อมูลตั้งต้น, สร้างบัญชีผู้ใช้
├── certs/              ใบรับรอง HTTPS เฉพาะเครื่อง (สร้างด้วย npm run gen-cert ไม่ commit)
├── scripts/            สคริปต์ช่วยงาน — สร้างใบรับรอง เก็บหลักฐานทดสอบ
├── backend/            ระบบหลังบ้าน Node.js + Express (ชื่อโฟลเดอร์ตรงกับส่วนประกอบใน C3)
├── frontend/           ส่วนติดต่อผู้ใช้ React
├── print-service/      บริการพิมพ์ใบเสร็จ ESC/POS (แยกกระบวนการ)
└── evidence/           ภาพหน้าจอและผลทดสอบสำหรับบทที่ 4
```

## การตั้งค่าเครื่องพิมพ์ใบเสร็จ

บริการพิมพ์ใบเสร็จทำงานเป็นกระบวนการแยกที่พอร์ต 4100 รับข้อมูลใบเสร็จแล้วแปลงเป็นคำสั่ง ESC/POS ส่งเครื่องพิมพ์ ตั้งปลายทางด้วย `PRINTER_INTERFACE` ในไฟล์ `.env` ได้สามแบบ

| ค่า | ใช้เมื่อ |
|---|---|
| `tcp://192.168.1.87:9100` | เครื่องพิมพ์ต่อผ่านเครือข่าย ให้เปลี่ยนเป็นหมายเลขไอพีของเครื่องพิมพ์จริง |
| `printer:SOML-Receipt` | เครื่องพิมพ์ต่อผ่าน USB โดยส่งผ่านคิวพิมพ์ของระบบปฏิบัติการ |
| `file://./evidence/printer-simulator` | โหมดจำลอง ใช้ตอนพัฒนาและทดสอบเมื่อยังไม่มีเครื่องพิมพ์ |

โหมดจำลองจะเขียนไฟล์สองชุดต่อใบเสร็จหนึ่งใบ คือ `.bin` ซึ่งเป็นสายไบต์ที่จะส่งเครื่องพิมพ์จริง ใช้ตรวจสอบคำสั่ง ESC/POS ได้ด้วย `xxd` และ `.txt` ซึ่งเป็นข้อความที่ถอดกลับมาอ่านได้ ใช้ตรวจความถูกต้องของเนื้อหาใบเสร็จ

ภาษาไทยส่งไปยังเครื่องพิมพ์ด้วยรหัส TIS-620 และสั่งเลือกตารางรหัสอักขระด้วยค่า `PRINTER_CODEPAGE` ซึ่งตั้งไว้ที่ 21 ตามเครื่องพิมพ์ตระกูล Epson **ถ้าพิมพ์ออกมาแล้วภาษาไทยเพี้ยน ให้เปิดคู่มือเครื่องพิมพ์หาหมายเลขตารางรหัส TIS-620 ของรุ่นนั้นแล้วเปลี่ยนค่านี้** และตั้ง `PRINTER_WIDTH_CHARS` ให้ตรงกับความกว้างกระดาษ คือ 48 สำหรับกระดาษ 80 มม. หรือ 32 สำหรับกระดาษ 58 มม.

## หมายเหตุสำหรับผู้พัฒนา

- `db/schema.sql` เป็นสำเนาของ `../Documents/assets/schema.sql` ถ้าแก้ต้องแก้ให้ตรงกันทั้งสองที่ เพราะฉบับใน `Documents/` เป็นฉบับที่อ้างอิงในปริญญานิพนธ์
- ห้าม commit ไฟล์ `.env` — มีรหัสผ่านฐานข้อมูลและหมายเลขพร้อมเพย์จริงของร้าน
- บทบาทผู้ใช้มี 3 ค่าตาม ENUM ในฐานข้อมูล คือ `sales` / `warehouse` / `manager` สิทธิ์ระดับผู้ดูแลระบบรวมอยู่ในบทบาท `manager`
