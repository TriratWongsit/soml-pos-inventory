# SOML — วิธีรันโปรแกรม

ระบบจัดการคำสั่งซื้อและตรวจสอบคลังสินค้า ร้านวัสดุก่อสร้างอำพรคอนกรีต
ระบบประกอบด้วยสี่หน่วยติดตั้ง (ตารางที่ 3.17 ของปริญญานิพนธ์) คือ หน้าจอผู้ใช้ · ระบบหลังบ้าน · บริการพิมพ์ใบเสร็จ · ฐานข้อมูล

## สิ่งที่ต้องมีก่อน

| สิ่งที่ต้องมี | รุ่นที่ใช้พัฒนา | ตรวจด้วยคำสั่ง |
|---|---|---|
| Node.js | 20 ขึ้นไป (เครื่องพัฒนาใช้ 22) | `node -v` |
| MySQL | 8.0 | `mysql --version` และ `mysqladmin ping` |

## ครั้งแรกที่ติดตั้ง (ทำครั้งเดียว)

```bash
cd soml
npm install              # ติดตั้งไลบรารีของทุกหน่วยติดตั้งในครั้งเดียว (npm workspaces)
cp .env.example .env     # แล้วเปิดแก้ค่าตามหัวข้อถัดไป
npm run db:reset         # สร้างฐานข้อมูล ตาราง สินค้า 783 รายการ และผู้ใช้ 4 บัญชี
```

`npm run db:reset` จะลบฐานข้อมูลเดิมทิ้งแล้วสร้างใหม่ทั้งหมด ถ้ามีข้อมูลขายจริงอยู่แล้วอย่าเรียกซ้ำ

### ค่าใน `.env` ที่ต้องแก้

| ตัวแปร | ต้องใส่อะไร |
|---|---|
| `DB_USER`, `DB_PASSWORD` | บัญชี MySQL ของเครื่องนั้น |
| `JWT_SECRET` | ข้อความสุ่มยาว ๆ — ระบบหลังบ้านจะไม่ยอมเริ่มทำงานถ้ายังเป็น `change-me` |
| `PROMPTPAY_ID` | เบอร์โทรศัพท์หรือเลขประจำตัวผู้เสียภาษีของร้าน ถ้าไม่ใส่ หน้าขายจะสร้างรหัส QR ไม่ได้ (ตอบ 503) |
| `PRINTER_INTERFACE` | `file://./printer-output` เมื่อยังไม่มีเครื่องพิมพ์ (เขียนใบเสร็จเป็นไฟล์แทน) · `printer:ชื่อคิวพิมพ์` เมื่อต่อ Epson TM-T82 ผ่าน USB |

ไฟล์ `.env` ถูก gitignore ไว้ ห้าม commit เพราะมีค่าลับของร้าน

## รันระบบ

```bash
cd soml
npm run dev
```

คำสั่งเดียวนี้เปิดทั้งสามหน่วยพร้อมกัน แล้วแสดงบันทึกแยกสีให้

| หน่วย | ที่อยู่ | ใช้ทำอะไร |
|---|---|---|
| หน้าจอผู้ใช้ | <http://localhost:5173> | **เปิดอันนี้ในเบราว์เซอร์** |
| ระบบหลังบ้าน | <http://localhost:4000> | ตรวจว่าทำงานอยู่ด้วย `/api/health` → `{"status":"ok"}` |
| บริการพิมพ์ | <http://localhost:4100> | รับคำสั่งพิมพ์จากระบบหลังบ้าน |

หยุดการทำงานด้วย `Ctrl + C` ที่หน้าต่างเดียวกัน

ถ้าต้องการเปิดทีละหน่วย (เช่น เวลาหาสาเหตุปัญหา) ใช้ `npm run dev:backend`, `npm run dev:print`, `npm run dev:frontend`

## บัญชีสำหรับเข้าสู่ระบบ

รหัสผ่านทุกบัญชีคือค่าของ `SEED_PASSWORD` ใน `.env` (ค่าตั้งต้น `Soml@2569`)

| ชื่อผู้ใช้ | ชื่อ-นามสกุล | บทบาท | เห็นหน้าจอ |
|---|---|---|---|
| `siriphan` | ศริพรรณ ศิริกันทา | พนักงานขาย | ขายหน้าร้าน |
| `somporn` | สมพร เขียวแก้ว | พนักงานขาย | ขายหน้าร้าน |
| `santi` | สันติ ศิริกันทา | พนักงานคลังสินค้า | คิวรอจ่าย ยืนยันจ่าย แดชบอร์ดปฏิบัติการ การแจ้งเตือน |
| `ning` | นิ้ง | ผู้จัดการ | ทุกหน้าจอ |

## ลองใช้งานให้ครบหนึ่งรอบ

1. เข้าด้วย `siriphan` → เลือกหมวดหมู่ แตะสินค้า ระบุจำนวน → กด "แสดงรหัส QR" → กด "ยืนยันรับชำระเงิน"
2. เปิดอีกหน้าต่างหนึ่ง (หรือโหมดไม่ระบุตัวตน) เข้าด้วย `santi` → คำสั่งซื้อจะขึ้นบนหน้าคิวเองภายในไม่กี่วินาที โดยไม่ต้องกดรีเฟรช
3. กด "เริ่มจัดของ" แล้วกด "ยืนยันจ่ายสินค้า" สองครั้ง → สต็อกถูกตัดและรายการหายจากคิวทุกหน้าจอ
4. เข้าด้วย `ning` → ดูแดชบอร์ด การแจ้งเตือนสินค้าใกล้หมด และประวัติการทำรายการ

ใบเสร็จที่พิมพ์จะไปอยู่ในโฟลเดอร์ `printer-output/` เมื่อยังไม่ได้ต่อเครื่องพิมพ์จริง

## รันชุดทดสอบ

ระบบมีการทดสอบสามระดับตามตารางที่ 3.22 ของปริญญานิพนธ์

```bash
# ระดับที่ 1 และ 2 — ไม่ต้องเปิดระบบไว้ ใช้ฐานข้อมูลทดสอบแยกต่างหาก
npm run db:reset:test     # เตรียมฐานข้อมูลทดสอบ soml_new_test
npm test                  # 130 ข้อ (หน่วย + การรวมส่วน)
npm run test:unit         # เฉพาะที่ไม่ใช้ฐานข้อมูล

# ระดับที่ 3 — ทดสอบผ่านหน้าจอจริงด้วยเบราว์เซอร์ ต้องเปิด npm run dev ไว้ก่อน
npx playwright install chromium   # ครั้งแรกครั้งเดียว
npm run test:system               # เดินตามเกณฑ์การยอมรับ AC-01..AC-11
```

การทดสอบระดับที่สามทำงานกับ **ฐานข้อมูลใช้งาน** เพราะต้องเรียกผ่านระบบที่เปิดอยู่จริง
จึงสร้างคำสั่งซื้อและตัดสต็อกจริง ถ้าต้องการเริ่มจากข้อมูลสะอาดให้ `npm run db:reset` ก่อน
ถ้าหน้าจอเปิดที่พอร์ตอื่น ให้ระบุ `SYSTEM_BASE_URL=http://localhost:5174 npm run test:system`

## เก็บหลักฐานสำหรับบทที่ 4

```bash
node evidence/measure-tc05.js       # TC-05 เวลาจากยืนยันรับชำระจนถึงหน้าจอคิว (WebSocket)
node evidence/measure-tc05.js sse   # TC-05 ผ่านช่องทางสำรอง
node evidence/measure-tc14.js       # TC-14 สิบเซสชันจากสามบทบาทใช้งานพร้อมกัน
npm run test:system                 # ภาพหน้าจอลง Documents/assets/screens/
```

ผลถูกบันทึกเป็นไฟล์ใน `evidence/` เพื่อให้ตรวจย้อนหลังได้ว่าตัวเลขในรูปเล่มมาจากการรันจริง

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `Port 4000 is in use` | มีระบบหลังบ้านเปิดค้างอยู่แล้ว ปิดด้วย `lsof -nP -iTCP:4000 -sTCP:LISTEN` แล้ว `kill` หมายเลขกระบวนการนั้น |
| หน้าจอเปิดที่ 5174 แทน 5173 | พอร์ต 5173 ถูกใช้อยู่ Vite เลื่อนพอร์ตให้เอง เปิดตามที่แสดงในบันทึกได้เลย |
| `JWT_SECRET ยังเป็นค่าตัวอย่าง` | แก้ `JWT_SECRET` ใน `.env` เป็นข้อความสุ่ม แล้วรันใหม่ |
| หน้าขายขึ้นว่ายังไม่ได้ตั้งหมายเลขพร้อมเพย์ | ใส่ `PROMPTPAY_ID` ใน `.env` แล้วรันใหม่ |
| `ER_ACCESS_DENIED_ERROR` | `DB_USER`/`DB_PASSWORD` ไม่ตรงกับ MySQL ของเครื่อง |
| คิวไม่อัปเดตเอง | ระบบหลังบ้านไม่ได้ทำงานอยู่ หรือเบราว์เซอร์ปิดช่องทางค้างไว้ ลองโหลดหน้าใหม่ |
