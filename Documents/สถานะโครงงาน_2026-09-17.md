**ตัวเลข ณ ตอนนี้**
- โค้ด 2,269 บรรทัด (ไม่รวม test) · เส้นทาง API 17 เส้นทางตรงตาราง 3.18 ทุกบรรทัด
- ทดสอบ **127 ข้อผ่านทั้งหมด**: unit 34 · integration 93 — ทุกข้ออ้างรหัส AC/TC/หัวข้อในเล่ม
- use case ที่ทำงานได้จริงผ่านหน้าจอ: **UC-01 ถึง UC-11 ครบ**
- ทดสอบ end-to-end แล้ว: ขาย → ใบเสร็จออก (ไฟล์) → คิวขึ้นเอง → จ่ายของ → สต็อกตัด → แจ้งเตือน → ประวัติ

**สิ่งที่ test พิสูจน์ให้แล้ว (ใช้เป็นหลักฐานบทที่ 4 ได้)**
- TC-01 สิทธิ์ตามบทบาท (ไม่แนบ/ปลอม/บทบาทผิด → ปฏิเสธทั้งสาม)
- TC-03 ยอดรวมตรง + QR ระบุยอดเดียวกัน
- TC-04 สร้าง 20 คำสั่งซื้อพร้อมกัน เลขที่ไม่ซ้ำ (เจอและแก้ deadlock ระหว่างทาง)
- TC-06 / AC-07 กดจ่ายพร้อมกัน สำเร็จ 1 ปฏิเสธ 1 สต็อกหักครั้งเดียว — ทั้งผ่าน HTTP และเรียกตรง 10 ธุรกรรม
- AC-08 สต็อกไม่พอ rollback ทั้งก้อน รวมกรณีหลายรายการ
- AC-06 / NFR-02 คิวรับเหตุการณ์ผลักใน < 3 วินาที (WebSocket และ SSE สำรอง)
- AC-09 แดชบอร์ดเท่ากับ SQL ตรง · AC-10 แจ้งเตือนเกิดเองโดยไม่เปิดดู

**การตัดสินใจระหว่างทางที่ควรจำ** (ตัดสินโดยเจ้าของโครงงาน)
- คอลัมน์ที่เล่มไม่พูดถึง: เก็บ `full_name`, `is_active` · ตัด `line_total`, `orders.created_at`
- สินค้า: เอาเฉพาะแถวข้อมูลครบ (783/1,135) · สต็อกไม่รู้ = 0 · reorder_point = 0 ให้ผู้จัดการตั้งเอง
- แผนภาพสถานะ: `picking → cancelled` อนุญาต (ตามตาราง 3.20)
- คิวค้าง: ตรวจเองทุก 60 วินาที (BR-05 เชิงรุก) ไม่รอผู้ใช้เปิดดู
- **ปุ่มจ่ายเงินสด: ไม่ทำ** เพราะเกินขอบเขตเล่ม (1.2.1 ระบุ QR พร้อมเพย์) — รอถามอาจารย์ก่อน
