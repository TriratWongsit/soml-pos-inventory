# โปรเจกต์นี้คืออะไร

ปริญญานิพนธ์ของผม ระบบจัดการคำสั่งซื้อและตรวจสอบคลังสินค้า ร้านวัสดุก่อสร้างอำพรคอนกรีต (SOML) ผู้จัดทำ นายตรัยรัตน์ วงษ์สิทธิ์ และนายพนาวุฒน์ อภิปสันติ
repo: https://github.com/TriratWongsit/soml-pos-inventory (public)

| โฟลเดอร์ | คืออะไร |
|---|---|
| `soml/` | แอปที่ใช้จริง: backend (Node.js + Express), frontend (React + Vite), print-service (ใบเสร็จ ESC/POS), db (MySQL schema + seed), tests, evidence |
| `เอกสารแต่ละบท/` | ฉบับล่าสุดของบทที่ 1–4, UseCaseX, SRS (pdf และ docx) ใช้ส่งอาจารย์ |
| `Documents/` บน GitHub | ฉบับเก่า ไม่ใช่ต้นทางล่าสุด อย่าใช้อ้างอิง |

ไฟล์ต้นทาง .md ของเล่มและสคริปต์สร้างเอกสารอยู่บน Mac เท่านั้น เครื่องนี้จึงแก้เล่มแล้วสร้าง PDF ใหม่ไม่ได้ ถ้าต้องแก้เล่ม ให้บอกผมว่าต้องไปทำบน Mac

# งานบนเครื่องนี้

เครื่องนี้เป็น PC Windows ที่ต่อเครื่องพิมพ์ใบเสร็จ Epson TM-T82 ผ่าน USB งานหลักคือ
1. ติดตั้งระบบตาม `soml/ติดตั้งบนWindows.md` ทีละขั้น ตรวจแต่ละขั้นให้ผ่านก่อนไปขั้นถัดไป
2. ตั้งเครื่องพิมพ์ให้ระบบพิมพ์ได้ (หัวข้อ 3 ในคู่มือ) โค้ดรองรับ Windows แล้วที่ `soml/print-service/lib/transport.js` วิธีคือแชร์เครื่องพิมพ์ชื่อ `AmpornOMS-Receipt` แล้วระบบสั่ง `copy /b ไฟล์ \\localhost\AmpornOMS-Receipt` การพิมพ์กับเครื่องจริงยังไม่เคยทดสอบ
3. ทดสอบ TC-13 (พิมพ์ใบเสร็จภาษาไทย ภายใน 5 วินาที ตาม NFR-05 และ AC-14) บันทึกเวลาที่วัดได้จริงและถ่ายรูปใบเสร็จ เพื่อเอาไปใส่บทที่ 4 บน Mac

ถ้ามีปัญหากับเครื่องพิมพ์ ให้หาสาเหตุจริงก่อนแก้โค้ด และบอกผมว่าแก้อะไรเพราะอะไร

# กฎที่ต้องยึด (สำคัญที่สุด)

1. อาจารย์ให้คะแนนจากการที่ผมอธิบายงานเองได้ ไม่ใช่ปริมาณเอกสาร อาจารย์เคยบอกว่างานส่วนใหญ่ดูเหมือน AI ทำ และจะสัมภาษณ์ให้เล่าตั้งแต่ปัญหา การเก็บความต้องการ requirement การแบ่ง use case ไปจนถึงการออกแบบ C2 และ C3 เพราะฉะนั้นให้อธิบายเหตุผลของการตัดสินใจให้ผมเข้าใจ ชี้ว่าข้อมูลอยู่ตรงไหนในเอกสารหรือโค้ดเพื่อให้ผมไปตรวจเอง เขียนสั้นพอให้จำได้ ถ้าเจอสิ่งที่อธิบายไม่ได้ให้บอกตรง ๆ การซ้อมสัมภาษณ์ (ถามแบบอาจารย์แล้วติคำตอบ) เป็นสิ่งที่ผมต้องการ
2. ขอบเขตโครงงานกำหนดโดยบทที่ 1 และบทที่ 3 ถ้าผมขอฟีเจอร์ที่ไม่มีใน FR, UC หรือตารางฐานข้อมูล ให้บอกก่อนว่าเกินขอบเขต แล้วหยุดรอ ห้ามลงมือทำ เคยเกิดขึ้นแล้วกับปุ่มรับเงินสดที่ทำเสร็จแล้วต้องถอดออก สิ่งที่อยู่นอกขอบเขต: รับเงินสด, ตรวจการโอนผ่าน API ธนาคาร, แจ้งเตือนผ่าน LINE/อีเมล, เชื่อม ERP, AI พยากรณ์, แอป mobile native, พักบิล/ใบเสนอราคา, ขายออฟไลน์, เงินเดือน, ปิดยอดประจำวัน
3. ตัวเลขทุกตัวในเล่มต้องมาจากการรันจริง หลักฐานอยู่ใน `soml/evidence` สิ่งที่ยังไม่ได้ทดสอบให้เขียนว่า "ยังไม่ทวนสอบ" ห้ามเขียนว่าผ่าน
4. ใช้รหัส EV FR NFR BR US UC AC TC ชุดเดียวกับบทที่ 3 เสมอ ห้ามสร้างรหัสใหม่เอง
5. ห้ามอ้างมาตรฐาน ISO หรือ IEEE ในเอกสารใด
6. เขียนภาษาไทย ใส่คำอังกฤษในวงเล็บตามหลังศัพท์เทคนิคครั้งแรก ไม่ใช้ตัวหนาเน้นคำในเนื้อความ ไม่ใส่กรอบสี ไม่ใส่ประวัติการแก้ไขเอกสาร
7. ถ้าผมให้เทมเพลตมา ทำตามโครงของเทมเพลตเป๊ะ ไม่เพิ่มหัวข้อเอง
8. ถ้าผมขอให้ทำใน Miro ให้ทำบนบอร์ด Miro จริง ไม่ใช่ทำหน้าเว็บมาแทน
9. repo เป็น public ก่อน push อะไรขึ้น GitHub ให้ถามผมก่อนทุกครั้ง ห้าม push ไฟล์ Excel สต็อกต้นฉบับของร้าน (`soml/db/seed/source/*.xlsx`) และห้าม push `.env`
