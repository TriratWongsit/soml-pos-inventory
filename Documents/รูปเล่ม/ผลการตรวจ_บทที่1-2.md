## 3. สิ่งที่ยังต้องตัดสินใจเอง

1. **หัวข้อ 2.1.4, 2.1.8 และ 2.1.9 ยังไม่มีการอ้างอิงเลยแม้แต่รายการเดียว** ทั้งสามหัวข้อกล่าวถึงทฤษฎี (การจัดการสถานะ การรวบรวมข้อมูลเพื่อการตัดสินใจ และการออกแบบประสบการณ์ผู้ใช้) โดยไม่มีแหล่งอ้างอิง ซึ่งเป็นจุดที่ถูกถามได้ว่านำทฤษฎีมาจากไหน ทางเลือกคือหาแหล่งที่อ่านเข้าใจจริงมาอ้างเพิ่ม หรือปรับข้อความให้เป็นการอธิบายแนวทางที่ใช้ในโครงงานแทนการอ้างว่าเป็นทฤษฎี ข้อควรระวังคืออย่าใส่รายการอ้างอิงที่ยังไม่ได้อ่าน เพราะถ้าถูกถามถึงเนื้อหาจะตอบไม่ได้

2. **ตำแหน่งของเอกสารอ้างอิง** ในไฟล์นี้อยู่ท้ายบทที่ 2 เพื่อความสะดวกในการตรวจ แต่ในเล่มฉบับสมบูรณ์ต้องย้ายไปไว้หลังบทที่ 5

3. **บทที่ 4 หัวข้อ 4.4.2 ประเมินสมมติฐานเฉพาะข้อ 1.4.1 ถึง 1.4.5 ยังไม่ได้ประเมินข้อ 1.4.6** ซึ่งเป็นข้อที่ว่าด้วยผลลัพธ์ที่คาดหวังจากการนำระบบไปใช้ ควรเพิ่มย่อหน้าในบทที่ 4 ระบุว่าข้อนี้ต้องรอข้อมูลจากการใช้งานจริงที่ร้าน มิฉะนั้นจะเหมือนตั้งสมมติฐานไว้แล้วไม่ตอบ

4. **คำว่า "คณะผู้จัดทำ"** ใช้อยู่ตลอดทั้งสองบท ถ้าโครงงานนี้มีผู้จัดทำคนเดียวต้องเปลี่ยนเป็น "ผู้จัดทำ" ให้ตรงกับหน้าปกและใบรับรอง

## 4. คำถามที่อาจถูกถามจากบทที่ 1 และบทที่ 2

1. สมมติฐานในหัวข้อ 1.4 พิสูจน์อย่างไร และผลออกมาเป็นอย่างไร (คำตอบอยู่ที่บทที่ 4 หัวข้อ 4.4.2)
2. ทำไมขอบเขตจึงไม่รวมการตรวจสอบการชำระเงินอัตโนมัติ (เพราะไม่มีสิทธิ์เข้าถึง API ของธนาคาร พนักงานขายจึงเป็นผู้ยืนยันการรับเงินเอง ซึ่งเป็นข้อจำกัดที่ระบุไว้ตั้งแต่ต้น)
3. งานวิจัยที่อ้างในหัวข้อ 2.3 อ่านมาจากไหน และแตกต่างจากระบบของเราอย่างไร (ตอบด้วยตารางที่ 2.1)
4. ทำไมเลือก C4 Model แทนการเขียนแผนภาพสถาปัตยกรรมแบบอื่น
5. ACID เกี่ยวข้องกับปัญหาของร้านอย่างไร (ตอบด้วยกรณีจ่ายของซ้ำและกรณีสต็อกไม่พอกลางธุรกรรม)
