# ภาคผนวก ข

# เอกสารการออกแบบซอฟต์แวร์ (Software Design Description)

ภาคผนวกนี้เป็นเอกสารการออกแบบซอฟต์แวร์ฉบับเต็มของระบบอำพร OMS ใช้คู่กับบทที่ 3 หัวข้อ 3.3 และ 3.4 ซึ่งสรุปการออกแบบและเหตุผลไว้แล้ว ภาคผนวกนี้เพิ่มรายละเอียดที่ผู้พัฒนาต้องใช้แต่ไม่จำเป็นต่อการอ่านเนื้อบท ได้แก่ ไฟล์และฟังก์ชันของแต่ละโมดูล พจนานุกรมข้อมูลของทุกตาราง และเส้นทางบริการทั้งหมด ตารางในภาคผนวกนี้สร้างจากไฟล์โครงสร้างฐานข้อมูลและไฟล์ประกาศเส้นทางของระบบรุ่นที่นำเสนอวันสอบ ส่วนตาราง คอลัมน์ และเส้นทางที่เพิ่มหลังการสอบแสดงไว้ในตารางที่ ซ.2

## ข.1 มุมมองบริบทและสถาปัตยกรรม (Context and Architecture View)

บริบทของระบบ หน่วยติดตั้ง ส่วนประกอบ และการติดตั้ง แสดงไว้แล้วในบทที่ 3 รูปที่ 3.3 ถึงรูปที่ 3.6 และการตัดสินใจเชิงสถาปัตยกรรมอยู่ในตารางที่ 3.20 ภาคผนวกนี้จึงไม่แสดงซ้ำ

## ข.2 มุมมองการแบ่งส่วนประกอบ (Decomposition View)

แต่ละโมดูลในตารางที่ 3.16 และ 3.17 อยู่ในโฟลเดอร์หรือไฟล์ของตนเอง และเปิดให้โมดูลอื่นเรียกได้เฉพาะฟังก์ชันที่ส่งออก ดังตารางที่ ข.1

**ตารางที่ ข.1** ส่วนประกอบของระบบหลังบ้าน ที่อยู่ในซอร์สโค้ด และฟังก์ชันที่ส่งออก

| รหัส | ส่วนประกอบ | ที่อยู่ในซอร์สโค้ด | ฟังก์ชันที่ส่งออก |
|:---:|---|---|---|
| BE-01 | ส่วนควบคุมการเข้าสู่ระบบ | `backend/modules/auth` | `login`, `me` |
| BE-02 | ส่วนควบคุมข้อมูลสินค้า | `backend/modules/product` | `list`, `getById`, `create`, `update`, `adjustStock` |
| BE-03 | ส่วนควบคุมคำสั่งซื้อ | `backend/modules/order` | `quote`, `create`, `getById`, `parseItems`, `nextOrderNo` |
| BE-04 | ส่วนจัดการคิวงาน | `backend/modules/queue` | `list`, `updateStatus`, `events`, `broadcast`, `attach`, `TRANSITIONS` |
| BE-05 | ส่วนควบคุมการจ่ายสินค้า | `backend/modules/dispatch` | `confirm` |
| BE-06 | บริการตัดสต็อก | `backend/modules/stock-deduction` | `dispatch`, `DispatchRejected` |
| BE-07 | ส่วนรวบรวมข้อมูลแดชบอร์ด | `backend/modules/dashboard` | `ops`, `exec` |
| BE-08 | ส่วนตรวจเงื่อนไขแจ้งเตือน | `backend/modules/alert` | `checkStock`, `checkQueueDelay`, `start`, `stop`, `list`, `markRead` |
| BE-09 | บริการบันทึกประวัติ | `backend/modules/audit-log` | `record`, `list`, `ACTIONS` |
| BE-10 | ส่วนเชื่อมต่อบริการพิมพ์ | `backend/modules/print-client` | `printReceipt` |
| SP-01 | ส่วนตรวจสิทธิ์คั่นหน้าเส้นทาง | `backend/middleware/auth.js` | `verifyToken`, `requireRole`, `clientIp`, `JWT_SECRET` |
| SP-02 | ส่วนตั้งค่าการเชื่อมต่อฐานข้อมูล | `backend/config/db.js` | `pool`, `withTransaction`, `database` |
| SP-03 | ไลบรารีสร้างรหัสคิวอาร์พร้อมเพย์ | `backend/lib/promptpay.js` | `buildPayload`, `crc16`, `normalizeTarget`, `field` |

หน้าจอ FE-01 ถึง FE-09 อยู่ในโฟลเดอร์ `frontend/src/pages/` หนึ่งโฟลเดอร์ต่อหนึ่งหน้าจอ โดยใช้ส่วนประกอบร่วมในโฟลเดอร์ `frontend/src/components/` และส่วนเรียกบริการในโฟลเดอร์ `frontend/src/services/`

## ข.5 มุมมองพฤติกรรม (Behavioral View)

พฤติกรรมของระบบแสดงไว้แล้วในบทที่ 3 ได้แก่ แผนภาพลำดับในรูปที่ 3.8 และ 3.9 แผนภาพกิจกรรมในรูปที่ 3.10 และแผนภาพสถานะในรูปที่ 3.11 การเปลี่ยนสถานะที่เส้นทางปรับสถานะทั่วไปยอมรับประกาศไว้ในโมดูล BE-04 ดังตารางที่ ข.10 ส่วนสถานะส่งมอบสำเร็จเกิดได้ทางเดียวคือผ่านธุรกรรมของ BE-06

**ตารางที่ ข.10** การเปลี่ยนสถานะคำสั่งซื้อที่เส้นทางปรับสถานะยอมรับ

| สถานะปัจจุบัน | เปลี่ยนเป็นสถานะใดได้ผ่านเส้นทางปรับสถานะ | บทบาทที่ทำได้ |

| รอจ่ายสินค้า (`awaiting_dispatch`) | กำลังจัดของ, ยกเลิก | กำลังจัดของ ทำได้ทั้งพนักงานคลังสินค้าและผู้จัดการ ยกเลิกทำได้เฉพาะผู้จัดการ |
