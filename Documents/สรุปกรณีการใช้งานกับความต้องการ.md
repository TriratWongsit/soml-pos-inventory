# 1. ความเชื่อมโยงที่ใช้ตรวจ

แต่ละกรณีการใช้งานเชื่อมไปยังสิ่งต่อไปนี้

| สิ่งที่เชื่อม | ความหมาย | ดูได้ที่ |
|-----------------------|-------------------------------------------------------------|-------------------------------|
| ความต้องการ (FR) | กรณีการใช้งานนี้เกิดขึ้นเพื่อตอบความต้องการข้อใด | ตารางที่ 3.8 |
| ขั้นตอนการทำงาน | ลำดับที่ผู้ใช้กับระบบทำ โปรแกรมต้องทำงานตามนี้ | ตารางที่ 3.9, 3.10 และ Use Case X หัวข้อ 4 |
| เกณฑ์การยอมรับ (AC) | เงื่อนไขที่ต้องเป็นจริง จึงจะยอมรับได้ว่ากรณีนี้ใช้งานได้ | ตารางที่ 3.11 และ Use Case X ภาคผนวก D |
| หน้าจอ (UI) | หน้าจอที่ผู้ใช้ใช้ทำกรณีนี้ | ตารางที่ 3.21 และบทที่ 4 หัวข้อ 4.1 |
| ข้อมูล (ERD) | ตารางในฐานข้อมูลที่กรณีนี้อ่านหรือเขียน | รูปที่ 3.9 และตารางที่ 3.19 |

# 3. กรณีการใช้งาน หน้าจอ และข้อมูล

| UC | หน้าจอ | ตารางที่อ่าน | ตารางที่เขียน |
|:---------:|---------------------------|--------------------------|--------------------------|
| UC-01 | เข้าสู่ระบบ `/login` | `users` | `audit_logs` |
| UC-02 | จัดการข้อมูลสินค้า `/products` | `products` | `products`, `stock_movements`, `audit_logs` |
| UC-03 | ขายหน้าร้าน `/pos` | `products` | `orders`, `order_items`, `audit_logs` |
| UC-04 | ไม่มีหน้าจอ ทำงานภายใน UC-03 | `orders` | `orders` |

| UC-06 | คิวรอจ่ายสินค้า `/queue` | `orders` | `orders`, `audit_logs` |
| UC-07 | ยืนยันจ่ายสินค้า `/dispatch/:id` | `orders`, `order_items`, `products` | `orders`, `products`, `stock_movements`, `audit_logs` |
| UC-08 | แดชบอร์ดปฏิบัติการ `/dashboard` | `orders`, `products` | ไม่มี |

# 4. ขั้นตอนการทำงานเทียบกับโปรแกรม

ตรวจขั้นตอนสำคัญของแต่ละกรณีกับโค้ดจริง

| UC | ขั้นตอนที่เขียนไว้ | ตำแหน่งในโค้ด |
|:---------:|----------------------------------------------------|--------------------------------|
| UC-01 | บันทึก LOGIN ลงประวัติเมื่อเข้าสู่ระบบสำเร็จ | `backend/modules/auth/index.js` บรรทัด 44 |
| UC-02 | ล็อกแถวสินค้า (FOR UPDATE) ก่อนปรับยอดคงเหลือ | `backend/modules/product/index.js` บรรทัด 155 |
| UC-03 | สั่งพิมพ์หลังบันทึกคำสั่งซื้อแล้ว พิมพ์ไม่ได้การขายยังสำเร็จ | `backend/modules/order/index.js` บรรทัด 141–152 |
| UC-04 | หาเลขล่าสุดแล้วบวกหนึ่ง ถ้าชนกันให้ลองใหม่ | `backend/modules/order/index.js` บรรทัด 84–87 และ 28–33 |
| UC-06 | เปลี่ยนสถานะได้เฉพาะตามลูกศรในแผนภาพสถานะ และตามบทบาท | `backend/modules/queue/index.js` บรรทัด 24–31, 117 |
| UC-07 | เปลี่ยนสถานะแบบมีเงื่อนไข ล็อกสินค้าเรียงตามรหัส หักเมื่อยอดพอเท่านั้น | `backend/modules/stock-deduction/index.js` บรรทัด 33, 42, 51 |
| UC-08 | โหลดใหม่เมื่อมีเหตุการณ์ และทุก 60 วินาที | `frontend/src/pages/dashboard-ops/index.jsx` บรรทัด 15 |
| UC-09 | เลือกช่วง 7, 30, 90 วัน และสินค้าขายดี 10 อันดับ | `frontend/src/pages/dashboard-exec/index.jsx` บรรทัด 18 และ `backend/modules/dashboard/index.js` บรรทัด 54 |
| UC-10 | แสดงรายการของวันนี้เป็นค่าเริ่มต้น | `frontend/src/pages/audit-logs/index.jsx` บรรทัด 18–19 |
| UC-11 | ตรวจคิวค้างเองเป็นระยะ ไม่ต้องรอผู้ใช้เปิดหน้าจอ | `backend/modules/alert/index.js` บรรทัด 86 |

# 5. สิ่งที่ยังไม่ครบ

| เรื่อง | รายละเอียด |
|------------------------------|-------------------------------------------------------------|
| UC-06 และ UC-09 ไม่มีเกณฑ์การยอมรับ | สองกรณีนี้มีขั้นตอนและทดสอบระดับการรวมส่วนผ่านแล้ว แต่ไม่มีเกณฑ์การยอมรับกำกับ จึงยังไม่มีเงื่อนไขที่บอกได้ว่าผู้ใช้ยอมรับเมื่อใด |
| AC-14 พิมพ์ใบเสร็จภายใน 5 วินาที | ผ่าน พิมพ์กับเครื่องพิมพ์ความร้อนจริงผ่าน USB ภาษาไทยถูกต้อง ใช้เวลาประมาณ 2.3 วินาที (TC-12) |
| การใช้งานจริงของผู้ใช้ | ยังไม่ได้ให้ผู้ใช้ที่ร้านลองใช้ |
